## Browser privacy and observation limits

Reproductions exposed a broker-filled password through Show Password, missing screenshot masking and private exception text on failed observations/captures. The adapter now remembers the filled input in a document-local `WeakSet`, keeps its observed value redacted after type changes and restores its private marker during observation. Follow-up review reproduced a direct preview before another observation after type/marker changes. Capture now checks document sensitivity independently and applies native black masks to every input and private-marked field in a credential-sensitive Playwright document. This deliberately hides other form inputs too. A fresh nonsensitive document returns to normal password-field and marker masking. Probe or capture/masking failures return no image and a fixed public error.

WebDriver screenshots fail closed with `screenshot_redaction_required` for a document that received a broker credential. Capture resumes after navigation to a fresh document that reports no broker-filled fields. These protections cover known fields; an authorized website can read its own password inputs, copy values elsewhere or alter page-side tracking. No hostile-website secrecy guarantee is claimed.

A separate reproduction acquired 600 element handles despite exporting only 150. Control selection now uses 5,000-element and 300-candidate scan budgets inside the page before creating remote handles, and exports at most 150 controls. Unused collections, failed observation handles and detached action handles are disposed. Results report `text_truncated`, `controls_truncated`, `control_scan_truncated` and per-control name/value truncation. Text output is capped at 24,000 characters, although collecting the page's `innerText` still precedes that limit. [Adapter source](../rdc/adapters.py) and [privacy/resource regressions](../tests/test_browser_privacy.py) record the behavior.

## Final verification and boundaries

The final frozen iMac run passed **147 tests in 55.091 seconds**, with no skips and exit code `0`; wrapper time was **55.655 seconds**. The host was **macOS 26.6.2 arm64 with Python 3.14.7**. All **35 recorded runtime/test inputs** matched their manifest and remained unchanged during the run. The [receipt](verification-results-0.1.0a2.json) contains their SHA-256 hashes.

The real Chromium pixel test passed a direct screenshot after a synthetic private fill, marker removal and Show Password type change, before another observation. The field was masked and its later observed value remained redacted. The real-SDK embedded UI tests also passed in their synthetic host. They cover immediate/pending ended-session recovery, preserved selection, hide/resume, approval waiting, zero-count clearing and browser labels. Earlier local browser skips were caused by the container's socket restriction; the final iMac execution supplies the browser evidence they could not provide.

Verification chronology remains visible: an initial 146-test run passed; a subsequent 147-test run failed only the older FIFO fixture's deadline, which included Python/Engine startup. The fixture now waits for readiness under a separate startup budget before triggering the FIFO operation under its **unchanged two-second deadline**. The final 147-test run passed. [Fixture](../tests/test_core.py).

A subprocess-still-running `ResourceWarning` was observed during the output-capture timeout fixture. No PID attribution was captured, so its cause and persistence after teardown remain unresolved. All final assertions passed. The HTTP response cleanup fix has its own regression and does not establish the cause of that subprocess warning.

Keychain tests replace the native API boundary, including low-level C API fixtures that assert metadata calls request no secret bytes. They open no real Keychain and establish no actual macOS ABI or OS-prompt result. The helper's same-item reference avoids a second broad lookup, but another authorized local process may edit that item between the metadata and password calls. Existing same-account shell and hostile-website limits remain in [SECURITY.md](../SECURITY.md) and [CREDENTIALS.md](CREDENTIALS.md).

The driver cleanup checks use a W3C fixture. Actual Safari, Windows browsers, native credential providers, physical phones and independent native desktops retain their own qualification requirements. Earlier iMac results remain historical evidence for their recorded sources; the 147-test receipt applies to this repaired release.

## Upgrade and recovery notes

- Remove and re-enroll older macOS aliases through owner administration with the explicit Keychain file. The outer mapping-file format remains version `1`; the macOS locator becomes version `2`. Enrollment alone reads no password and grants no fill permission.
- Preserve cloud request IDs, worker retry keys and the relay journal. An `undeliverable` result requires inspecting the worker before another attempt. Original payloads have bounded retention, while identity records remain to prevent replay; aggregate journal cleanup is future work.
- If WebDriver reports `webdriver_cleanup_required`, list sessions and close the marked session. Its existence means cleanup remains unresolved.
- Refresh Sessions to update the preview's job and general action-review counts. Credential consent remains in authenticated owner administration. Its permission modal, the OS authentication prompt and the embedded preview have distinct roles.
