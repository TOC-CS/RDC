# Compatibility and qualification

Treat this as source-release context dated 2026-11-15 for core 0.1.0a4. Mobile support begins with core 0.1.0a3; private diagnostics begin with core 0.1.0a4. Source, installed worker, deployed gateway, saved plugin guidance and the current host catalog can be at different revisions. Prefer later explicit execution evidence and current tool schemas. An advertised adapter identifies an implementation; qualification requires recorded execution on the intended device and host.

| Route | Current evidence and boundary |
| --- | --- |
| Local macOS worker | File, durable-job, and independent Chromium workflows have run through local ChatGPT/Codex. Browser sessions survived client disconnection while the worker remained alive. The frozen core 0.1.0a4 source passed 254 macOS tests with no skips, with all 54 hashed files unchanged. Activation of that source and the matching gateway remains a separate verification step. |
| Private cloud connection | Native connection/status/preview-open tools succeeded in production ChatGPT on the audit baseline. The gateway is owner-private. Mobile and diagnostics capabilities require the matching active worker, gateway deployment and client catalog. A current heartbeat alone does not prove that a queued worker call can complete. Production embedded rendering and a completed approved live cloud workflow remain separate checks. |
| Private diagnostics | Core 0.1.0a4 adds read-only incident history and observed relay recovery. POSIX capture requires the documented Python/filesystem capabilities. The frozen macOS source gate passed; qualify the activated worker separately. Windows capture is disabled with `unsupported_platform`, while ordinary worker and relay operations continue. Reports do not prove complete capture, worker liveness or repair of a user task. |
| Embedded MCP Apps component | The official SDK and component ran in a sandboxed synthetic host with preview controls, pending-operation recovery, resize/mode handling, and lifecycle checks. These fixtures do not prove production ChatGPT, Codex, or Claude host behavior. |
| Claude | Configuration/protocol support exists. Actual Claude model execution and embedded rendering remain unverified. A text-only client cannot be assumed to display a component. |
| Safari | The real safaridriver route was attempted and blocked by disabled Allow remote automation. The owner setting was preserved. Playwright WebKit cannot substitute for real Safari qualification. |
| Windows | Historical hosted runs exposed CRLF and synthetic Mac-path fixture assumptions. Core 0.1.0a4 also fixes five embedded-contract failures caused by CRLF import parsing. Assess the exact revision using current hosted results; native Windows input and credential providers remain separately unqualified. |
| Android | ADB and native Appium UiAutomator2 routes are implemented, including gestures and privacy-checked preview. Protocol fixtures passed. Pairing, permissions and real phone/tablet/emulator qualification remain owner/device-specific work. |
| iPhone/iPad | Dedicated native Appium XCUITest sessions and preview are implemented, with observation-bound touch controls and secure-field refusal. Protocol fixtures passed. Actual hardware/simulator behavior, signing/trust setup and mobile saved-password access remain unqualified; native credential filling is unsupported. This release record establishes no physical iPhone 17 Pro Max, other iPhone, iPad or simulator acceptance. |
| Native desktop independence | Shared desktop input can affect the user's cursor/focus. Independent native desktop/display/VM provisioning and native live streaming remain incomplete or unqualified. |
| Saved-password providers | Synthetic credential, owner-consent, redaction, and browser tests passed. Actual native Keychain, Windows Credential Manager, browser-manager, and mobile provider access require separate qualification. |

The 0.1.0a4 source defines 52 core tools and the gateway adds 2 cloud recovery/status tools. This source count does not establish the currently connected catalog. The installed worker, deployed gateway or cached host may still expose an earlier revision. Check the connected App and a successful worker status result before claiming a route is usable. Follow [mobile guidance](mobile.md) for phones and tablets and [diagnostics](diagnostics.md) for private incident reports.

Browser sessions currently belong to the daemon and control one page each. Broad popup, tab, frame, upload, and download workflows need further work. Public multi-user onboarding and an AI-provider public directory listing are separate from this private App and the open-source repository.

Do not claim unrestricted control of every device function, a universal embedded-window API, elimination of operating-system consent, or a measured performance advantage without evidence for the specific workflow. Continue useful authorized work through the routes that are actually available.
