# Compatibility and qualification

Treat this as source-release context dated 2026-11-15 for core 0.1.0a5. Mobile support begins with core 0.1.0a3; private diagnostics begin with core 0.1.0a4 and are preserved in a5. Source, installed worker, deployed gateway, saved plugin guidance and the current host catalog can be at different revisions. Prefer later explicit execution evidence and current tool schemas. An advertised adapter identifies an implementation; qualification requires recorded execution on the intended device and host.

| Route | Current evidence and boundary |
| --- | --- |
| Local macOS worker | File, durable-job, and independent Chromium workflows have run through local ChatGPT/Codex. Browser sessions survived client disconnection while the worker remained alive. The frozen core 0.1.0a5 source passed 256 macOS tests in 106.095 seconds with no failures, errors, skips or ResourceWarning lines; all 54 hashed inputs remained unchanged. Separate activation verification matched all 52 live source inputs, retained the complete previous runtime and preserved protected state. A native ChatGPT status call subsequently confirmed the same worker on 0.1.0a5. |
| Private cloud connection | Native connection, worker-status, preview-open and diagnostic tools succeeded in production ChatGPT. The matching a5 gateway reached terminal deployment success after nine gateway tests, TypeScript checking and a production build passed. The gateway remains owner-private. The later host catalog exposes 53 model-visible tools, matching the 54-tool server catalog with one app-only preview-frame tool. A current heartbeat alone does not prove that a queued worker call can complete. Production embedded rendering and a completed approved live cloud browser workflow remain separate checks. |
| Private diagnostics | Core 0.1.0a4 adds read-only incident history and observed relay recovery, preserved in a5. After the a5 gateway deployment, the native ChatGPT report returned `available: true`, `storage_status: ready`, `incomplete: false` and `capture_scope: retained_history_and_current_process`. POSIX capture requires the documented Python/filesystem capabilities. Windows capture is disabled with `unsupported_platform`, while ordinary worker and relay operations continue. Reports do not prove complete capture, worker liveness or repair of a user task. |
| Embedded MCP Apps component | The official SDK and component ran in a sandboxed synthetic host with preview controls, pending-operation recovery, resize/mode handling, and lifecycle checks. A later production ChatGPT opening showed "App unavailable" although the native preview tool returned successfully. Its cause remains unconfirmed; synthetic fixtures and successful tool responses do not prove production rendering. |
| Claude | Configuration/protocol support exists. Actual Claude model execution and embedded rendering remain unverified. A text-only client cannot be assumed to display a component. |
| Safari | The real safaridriver route was attempted and blocked by disabled Allow remote automation. The owner setting was preserved. Playwright WebKit cannot substitute for real Safari qualification. |
| Windows | Historical hosted runs exposed CRLF and synthetic Mac-path fixture assumptions. Core 0.1.0a4 also fixes five embedded-contract failures caused by CRLF import parsing. Assess the exact revision using current hosted results; native Windows input and credential providers remain separately unqualified. |
| Android | ADB and native Appium UiAutomator2 routes are implemented, including gestures and privacy-checked preview. Protocol fixtures passed. Pairing, permissions and real phone/tablet/emulator qualification remain owner/device-specific work. |
| iPhone/iPad | Dedicated native Appium XCUITest sessions and preview are implemented, with observation-bound touch controls and secure-field refusal. Protocol fixtures passed. Actual hardware/simulator behavior, signing/trust setup and mobile saved-password access remain unqualified; native credential filling is unsupported. This release record establishes no physical iPhone 17 Pro Max, other iPhone, iPad or simulator acceptance. |
| Native desktop independence | Shared desktop input can affect the user's cursor/focus. Independent native desktop/display/VM provisioning and native live streaming remain incomplete or unqualified. |
| Saved-password providers | Synthetic credential, owner-consent, redaction, and browser tests passed. Actual native Keychain, Windows Credential Manager, browser-manager, and mobile provider access require separate qualification. |

The 0.1.0a5 source defines 52 core tools and the gateway adds 2 cloud recovery/status tools. On the later 2026-11-15 checks, the connected host exposed 53 tools to the model; `rdc_preview_frame` is app-only. Host catalogs and account-routing fields can differ across sessions. Supply an advertised account `link_id` only where the current schema requires it, using the selection and recovery rules in [cloud operations](cloud-operations.md). These dated observations do not replace checking the current connection and worker before a new workflow.

The native `rdc_mobile_list` call succeeded with `available: false`, empty `profiles` and empty `sessions`. Mobile tools are discoverable, but this worker has no configured mobile profile. Follow [mobile guidance](mobile.md) for owner device setup and separate hardware qualification, and [diagnostics](diagnostics.md) for private incident reports.

Browser sessions currently belong to the daemon and control one page each. Broad popup, tab, frame, upload, and download workflows need further work. Public multi-user onboarding and an AI-provider public directory listing are separate from this private App and the open-source repository.

The a5 repairs keep an owned-child wait reachable after termination cleanup raises and keep credential alias, grant and decision controls consistently busy during owner requests. The primary error remains authoritative, uncertain process exit remains explicit, and failed credential removal requires an explicit retry. The passing native run does not establish the cause of historical hosted process warnings. The independent repair guardian is under development and is not installed or enabled by this release.

Do not claim unrestricted control of every device function, a universal embedded-window API, elimination of operating-system consent, or a measured performance advantage without evidence for the specific workflow. Continue useful authorized work through the routes that are actually available.
